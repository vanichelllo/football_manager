# Головний тренер

Браузерний футбольний менеджер для себе: реальні ліги, клуби й гравці.
23 ліги: УПЛ і Перша ліга України, Англія, Іспанія, Італія, Німеччина, Франція (кожна з другим дивізіоном),
Португалія, Нідерланди, Туреччина, Польща, Бельгія, Шотландія, Греція, Чехія, Данія, Австрія й Швейцарія —
396 клубів і понад 11 000 гравців. Підвищення й виліт, три єврокубки за новим форматом, збірні з відбором і турнірами.
Старт — сезон 2026/27, далі — скільки завгодно сезонів.

У грі: тактика й матчі наживо з керуванням, сезон із таблицями, кубки країн і єврокубки, розвиток і травми
гравців, юнаки з академій, трансфери й контракти, фінанси й правління (можуть звільнити), мораль, промови й
прес-конференції, персонал і стадіон, збірні, профіль тренера з ліцензіями, бачення правління, розмови
й обіцянки гравцям, досягнення, роздягальня, молодіжна команда U-21, агенти, спонсори й фінансовий фейр-плей, медіа,
дербі, скаути по світу, пошук і графіки, звук трансляції, режими «Виклик» і швидкий, синхронізація між пристроями,
редактор гравців і клубів, збереження у файл. Як усе влаштовано — екран «Довідка» в грі
й `docs/PLAN.md`.

## Як грати

- **Локально:** відкрийте `index.html` у браузері (подвійний клік). Сервер не потрібен.
- **Онлайн:** один раз увімкніть GitHub Pages (Settings → Pages → Source: **GitHub Actions**). Після кожного
  злиття в `main` workflow «Публікація» проганяє тести й викладає гру за посиланням
  `https://<ваш-логін>.github.io/football_manager/`. Для приватного репозиторію GitHub Pages доступний лише на
  платних планах GitHub; на безкоштовному — тільки для публічних.
- **Офлайн:** відкрита з сайту гра працює й без інтернету (service worker) і встановлюється як застосунок
  («Додати на головний екран»). Окремий файл без сервера й мережі: `npm run bundle` → `dist/golovnyi-trener.html`
  (на сайті — `golovnyi-trener-offline.html`).

Збереження лежить у браузері (IndexedDB): три слоти кар'єри й контрольні точки останніх чотирьох тижнів
(відкат — у «Налаштуваннях»). На інший пристрій кар'єру переносять файлом або кодом збереження.

## Звідки дані

| Що | Джерело |
|---|---|
| Ліги, склади, клуби, стадіони, кольори | Wikipedia (CC BY-SA 4.0) |
| Дата народження, зріст, позиція, матчі за клуби й збірну | Інфобокси статей гравців у Wikipedia |
| Українські назви клубів і гравців | Wikidata (CC0); якщо мітки немає — назва статті в українській Wikipedia; для гравців збірної України без статей — транслітерація з латиниці (`tools/lib/translit.js`, наближено) |
| **Атрибути 1–20, рівень, потенціал, ціна** | **Власна формула** (`tools/lib/ratings.js`) |

Атрибутів у справжньому футболі немає, а бази інших ігор чужі, тож ми рахуємо їх самі з фактів:
сила ліги, місце клубу за два минулі сезони, вік, позиція, матчі за збірну (з урахуванням її рівня),
регулярність ігор, зріст, результативність. Логотипів немає (торгові марки), замість них — кольори клубу.

## Як оновити базу

```bash
node tools/build-db.js     # у хмарному контейнері: NODE_USE_ENV_PROXY=1 node tools/build-db.js
```

Скрипт збирає дані заново (Wikipedia обмежує частоту запитів, тож перший запуск триває десятки хвилин;
відповіді кешуються в `.cache/` на тиждень, кожна стаття окремо) і пише `data/db.js` та `data/db-report.txt`
зі списком того, що не вдалося розпізнати.

**Збереження переживають оновлення бази.** Id клубів і гравців рахуються з назви статті у Wikipedia, тож після
перебудови той самий гравець має той самий id: кар'єра продовжується з новими складами, а ваші зміни
(трансфери, розвиток, редагування) лишаються поверх. Нові гравці бази з'являються в клубах, гравці, яких
у базі більше немає, у вашій кар'єрі лишаються як були. Давні збереження з порядковими id (`c12`, `p345`)
переводяться автоматично за таблицею `legacyIds` у базі.

Щоб оновити склади посеред сезону: збережіть кар'єру, перебудуйте базу, злийте зміни — і продовжуйте.
